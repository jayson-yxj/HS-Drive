# M8-0 — Architecture Decision Review

**下一主要研发优先级：恢复六摄三维视觉感知研究，先补齐单个成熟框架的 P0 可行性证据。有界在线规划核心作为次优先级，暂不实现。**

日期：2026-10-24。依据：`b3dab191485dfe6da883d0d361064f02522b1a9c`。分支：`feat/m8-0-architecture-review`。决策状态：`ReviewCompleted / ImplementationNotAuthorized`。这是一份研发顺序与退出条件决策；后续具体里程碑需要用户单独批准，不能据此自动开始实现、环境部署、模型前向或训练。

## 决策理由

1. **最直接的项目缺口仍是可靠 RGB 空间感知。** M5-O 已扩大到 20 个训练位置、每种子 642/658 个可靠训练候选，Direct 仍不能稳定胜过 Geometry Prior；独立风险阈值没有获得合格覆盖。继续旧 Head 搜索没有研究依据。与此同时，成熟相机 3D 框架此前停在权重获取，尚未获得一次实际前向与 CARLA 合同结果。该信息缺口比再次叠加自定义模块更值得先补齐。
2. **M7 已形成有价值的离线评价资产，在线化需要另一个工程问题的解法。** F 在两个新最终序列增加 55 个继续行驶选择，历史 205/1662 与 7/7 保持；但 666/671 次完整结果过期。静态缓存约 99% 命中仍没有明显总时延收益。下一步若做 Planner，应研究有界核心与时效交接，不继续自动追加 M7-F 候选或局部调参。
3. **单人开发应先取得一个有退出条件的关键结论。** 一个模型的资产/环境/六摄前向/坐标可行性任务可设约 5 人日止损上限；新核心离线原型预计约 4–8 人周，且不能自动解决车辆低速执行和 200ms 交接问题。这是资源排序估计，非承诺工期或性能保证。
4. **感知优先并不意味着车辆控制已准备好。** 保留 Oracle 仿真工程及全部故障记录，停止视觉输出接线。若 P0 失败，就报告明确 NoGo 并重新决定后续任务，不自动换框架、恢复 Direct 训练或转而启动另一项大型实现。

## 时间合同决定了在线准入仍不能批准

保留 5Hz Planner、20Hz Controller 与当前默认代码。M7-D/E 的研究准入是原 snapshot +200ms；历史在线 Worker 默认 350ms 是另一合同，不能拿来让 M7 通过。规划计算、IPC、输入年龄、交付、Safety、控制和 tick 长尾必须分开测量。

如果 5Hz 每 200ms 才采新快照，且计划仅有效 200ms，非零计算时间会造成旧计划到期与新计划交付之间的空档。核心 <200ms 不等于每个 50ms 控制时刻都有可用计划。新鲜状态重新认证、相位调度或空档降级的可行性需要独立设计证明，本轮不扩有效期、不改默认安全合同。[预算与交接推导](../reports/m8_0_compute_budget.md)。

建议未来核心研究目标不高于 100ms，将剩余 200ms 总预算留给输入年龄、交付、安全与余量；这只是设计分配。不能用理论提速、P95 或短测试最大值批准在线控制。六秒安全预测、原车身/道路/停车余量与 Unknown 语义不放松。

## 后续可申请的范围

优先申请的是**有限可行性证据获取**，不是模型替换：官方可追溯权重和 SHA → 独立环境/官方 I/O → RTX4090 原规格六摄实际前向 → CARLA 坐标和输入隔离验证。当前缺少这些证据，不能把“申请采用 PETR”写成 Go。预算、停止规则、必要合同与评测分母在[感知就绪度](../reports/m8_0_perception_readiness.md)中具体列出。

获得 P0 证据后也只允许提出下一个受控域诊断/适配任务。冻结官方权重的零样本域偏移、训练可学习性、独立泛化、风险覆盖、运行时及驾驶安全继续单独验收。旧 M5-O Sealed 只能做回归；若后续发生选择或适配，最终结论需要新独立位置。

规划 B 保留为第二优先级，只接受后续单独批准的有界离线原型任务；不与视觉 P0 同时全面移植。Bench2Drive 保留兼容环境、附加地图、单 Tick Owner 与独立评价计划，不运行官方 220 路线。长期 Dense BEV + Sparse Query + Occupancy + Temporal + Planner 技术主线保持，默认视觉/Depth/48 LID/HeightSplat 不变。
