# M6-C 决策：保守能力估计不等于可执行停车控制

基线 `f047ade`；候选分支 `feat/m6c-safe-stopping-dynamics`。最终总体 **Partial / CandidateNoGo**。不替换默认控制器，不进入倒车泊车，不修改原车辆Physics，不使视觉输出驱动车辆。

## 1. 已能重复确认的现象

四处轻坡/平路、两次重复、自然起步探针表明：冷启动自动挡Throttle .10在6s内不能有效起步；.15约3.6s后突然起步。预置前进1挡明显改变延迟，却没有满足原始Jerk门槛；warm initialization同样改变响应。初始挡位/传动/接触状态共同影响动力学，不能把gear0→1的时序相关写成唯一原因。

Road126与独立Road66的下坡coast在20s内不能停稳，原coast近似存在结构失配。Brake .01仍可引起十几至二十多m/s²的真实减速度，不是可以直接当舒适执行器的线性小命令。原始速度导数、API加速度、250ms指标均保留；小幅控制命令不保证小幅实际响应。

上述是有限原配置的可重复现象，不是“所有控制器在原Physics上都不可能舒适”的数学证明。

## 2. 目标几何和本轮实现缺陷

M6-B的末端1m保留与辅助点抵消成立，目标没有合法移动理由。Actor原点与完整OBB几何差异应处理，但数厘米偏置不足以解释道路126丢失约2.75m安全余量。

本轮初始D犯了不同错误：以减速触发距离替代实际remaining传给C，污染HOLD目标判断。该版本正式结果均排除出有效D候选分子，保留源码和日志。修复D2只替换减速触发阈值，真实remaining始终不变，原目标和门槛不变。修复后重跑完全相同预声明D任务，无参数搜索。

D2仍在上坡/近终点发生提前减速后的反复微动、回滑、超调与边界接管，12个固定终点试验0通过，C为6/12。故本轮不能把失败全归为历史目标几何，主要剩余问题是**停车能力估计与实际执行、保持、恢复之间不自洽**。

## 3. 包络资格

开发道路27/126拟合，验证道路66/170只验证。预声明的速度分段最大距离加响应/坡度余量，在本批有限支持验证里未低估已观测停车距离；下坡coast明确不提供有限保证。支持数和相关性并列，未停稳数据作为截尾下界。

**Go：只作带来源和支持域的研究性风险估计器。No-go：安全认证、完整道路泛化或正常停车执行器。** 包络的brake_001能力假设不代表D实际使用普通.01制动。D保留C执行；余量不足触发原brake=1紧急路径。即使最终间距改善，若靠紧急制动完成，也不认证正常停车能力。

保守模型可能导致过早减速，C中的HOLD与恢复条件可能使车辆重新加速/回滑，逐时刻边界不是一次性可执行轨迹证明。需要未来单独设计能跟踪距离目标和保持可达集合的执行策略，但本轮不自动进行E或扩大调参。

## 4. 原始舒适性、绕行与故障保护

原始启动和制动Jerk门槛没有通过。不会剔除startup或只给250ms结果。不削弱紧急制动换取低Jerk。

冻结C的合法绕行、移除恢复单独复测；D2的路径绕过与终点停车分开判断。零碰撞不等于守住3m，不等于无道路边界，也不等于完整绕行任务通过。突然出现导致前置余量不足的样例仍计入间距失败，必须显式降级；不要删除它们提高比例。

## 5. Runtime

历史178.08ms可完整重建为tick阻塞、记录、休眠/唤醒、当前pre-apply；本轮记录同负载行驶C/D、原始server snapshot timestamp、请求队列等待、Worker执行和OS/GPU关联。低频`/proc`和client计时只能界定阻塞/调度关联，不能分解UE内部渲染与PhysX。

**严格20Hz保持Partial。** 同一场景重复的平均频率不能认证最大控制周期。全部运行长尾/失败在总账保留，不以4×600短测覆盖，不reset deadline、不补发tick。本轮不继续盲目亲和性组合搜索。

## 6. 后续允许范围

不批准默认Controller升级、真正倒车泊车、复杂交通、视觉控制、正式Occupancy或PETR迁移。允许下一轮在新的独立位置验证一个预声明、可解释的低速执行方案：距离/速度/保持状态真实合同、明确的物理可行区间，以及紧急保护的独立性。若要改变Physics，必须另外授权、独立版本和分支，禁止与当前成绩混比。

本批修复是在看到评测结果后进行的工程纠错，不再称完全盲测。候选升级必须新场景验证；当前门禁不会因模型上界在少量样本成立而自动关闭。
