# M8-G Architecture Decision

决策：**停止当前 OpenDRIVE + overlap-ray 混合放置器的自动扩展**。保留实现作为研究诊断基线，状态 `Partial / PlacementFeasibilityNoGo`。不接续阈值搜索、不自动启动 M8-H，不批准训练和视觉控制。

80 个预声明候选中 28 个通过两 phase 几何代理，但第一处 Development 没有可接受车辆，无法执行两处完整 Smoke。没有新的最终 Actor、渲染身份或反事实闭合证据。仅凭候选通过率不能恢复数据采集。

本轮缩小了根因范围：NONE 大量吻合交通触发体；Any 类型车道查询在真实宽车道内选择了相邻窄车道；树木 OBB 过于保守且不能提供完整净空。它们是不同证据源的语义问题，不适合通过扩大允许标签或降低 lane inset 一起解决。原 7 个请求严格分类仍为 0 确认物理非法、0 全条件证实安全误拒、7 未完全闭合。

下一次单独批准的技术决策应比较：

| 方案 | 能复用的证据 | 必须额外验证 | 单人维护代价 |
|---|---|---|---|
| 原生车辆 Spawn Point | 地图作者声明的车辆生成位置 | Actor 最终足迹、地面层、周围障碍、相机可见性与身份；推荐点不等于物理接触保证 | 较低，覆盖受位置集合限制 |
| 行人导航点 | 行人导航区域支持 | 地面高度、可达类别、局部障碍、随机种子、最终姿态与身份 | 中等，需固定候选预算及可复现选择 |
| 明确审核的场景模板 | 一次性逐目标几何/身份审查 | 地图版本绑定、布局相关性、位置组隔离、修改后重审 | 中等，初期覆盖有限但证据清晰 |

推荐先评审“小型审核模板 + 原生 spawn/navigation 候选来源”，继续用统一历史目标足迹预检及现有身份管线。不要将推荐点直接等同自然场景通过，也不要把导航点当独立 Final。历史覆盖仍不完整，需新数据分组独立决策。

如果将来研究修正射线通道，首先需要区分 trigger 与实体 hit component、保持水面/建筑/真实悬空反例、完成全车/人体体积净空审查；本轮没有实现这种放行规则。Driving 类型查询纠正也只能作为独立、有限的诊断候选，不能删除原安全检查。

工程诊断完成、代理几何通过、自然场景合格、独立训练资格、视觉安全是五个独立状态。本阶段没有把后四者自动标为 Passed。
