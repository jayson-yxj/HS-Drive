# M6-B 架构决策

基础 `7ec866f`，候选分支 `feat/m6b-oracle-maneuvers`。这是 Oracle 工程实验，不改变 Hybrid Spatial Driving 的感知技术基线。

## A：低速停车 — Partial；不替换默认控制器

历史9m路线的84.13%完成率包含固定1m导航保留量，以及约0.428m相对于内部目标的残余误差。1m解释几何差额的一部分，不代表删除它即可修复车辆动力学。M6-B通过显式停止位姿和旧Planner适配，保留障碍物3m距离。B仅目标语义、C再改控制器；配对相同Physics。

有限停车对照：A 0/8、B 4/8、C 6/8通过位置/航向/稳定保持/道路要求。C在第二位置9m试验越过目标约0.689/0.716m；普通三种导航路线两重复都未通过新增终点门槛。新控制器不能稳定覆盖旧导航行为，不升级默认。

所有停车臂均未通过预声明舒适性联合门禁。恒定0.15油门会在延迟后伴随gear0→1产生大的真实速度变化；0.10和短时缓升油门则未有效启动。说明仅控制命令平滑不足以保证物理加速度/Jerk平滑，但不能由此证明所有可能控制方法或原Physics都不可行。停车/启动、普通制动、紧急降级需独立建模；不能过滤尖峰后宣称通过。

**下一步只允许有明确假设的动力学/跟踪实验。** 应先验证同一车辆启动离合/挡位/接触状态、道路坡度和紧急制动释放后的响应，给出可行包络，再决定是否研究独立版本Physics。不要继续在本批评测上反调PID。不启动倒车泊车；前进停车不是自动泊车。

## B：静态绕行 — 仅限受控几何研究

确定性局部路径在两处同向双车道、Broken且允许双向变道的场景完成绕行和返回，障碍移除后也有恢复能力。它解决了M6-A只能停住而无法绕行的一项工程缺口。

拒绝路径必须和实际停车安全分别验收。道路126双车道阻塞时虽然正确给出 `NoFeasibleBypass`，车辆滑行侵入原3m停车余量，需当前碰撞保护接管。没有碰撞不足以证明安全拒绝。道路170结果与126不一致，保留Partial。

不把地图Driving查询或Actor OBB冒充精确路缘/渲染Mesh；离线车身网格包括OBB偏置、roll/pitch及安全膨胀，仍有采样不确定性。曲率约束、完整六秒轨迹Safety与当前碰撞保护均保留。尚无动态交通绕行、路口变道、道路法规全面验证。

**Go：隔离的Oracle候选和故障回归基础。No-go：通用绕障、自动部署或复杂交通扩大。** 先解决原3m余量的车辆可执行性，再增加场景。

## C：墙钟控制周期 — Partial

历史133.16ms控制间隔与前一帧131.60ms `world.tick()`对应。客户端计时只能定位阻塞边界，不能确定UE内部渲染、Physics、OS调度谁是根因。

M6-B使用单调时间、固定50ms槽位、显式超期/跳槽、无补tick。Cpu affinity是有限重复对照，不是硬核独占或GPU隔离；tick-only与行驶场景负载不同。即使某一重复的最大值下降，也不能与旧调度器短测做因果性能结论。

**No-go：严格20Hz认证。** 保留Worker原始时间戳、0.35s过期降级及六秒Safety；不通过缩短预测期、reset deadline或改统计分母取得通过。后续只有明确的tick内部profile/部署隔离假设才追加实测，不重跑无目的长矩阵。
