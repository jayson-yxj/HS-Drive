# M6-F architecture decision

状态：**Partial — ObservabilityResearchGo / NormalControlNoGo**。本阶段不批准正常Oracle闭环Pilot、主模拟器迁移或新的Physics搜索。

1. **采用独立CARLA0916_PhysicsP0作可观测性研究基线。** 真实服务端和匹配SDK已运行，获得轮速、滑移、载荷、轮胎调试力/扭矩和传动RPM/Gear。它优于0915原API的车身级观测，不是现实Tesla动力学验证。保留0915作为HS-Drive主后端。
2. **不同时开发0915完整源码插桩。** 0916已满足有限命令—轮端—车身研究需要，避免昂贵并行移植。实际刹车扭矩、平滑模拟输入、接触冲量和子步时序依旧缺失。需要完整根因时，应先为0916设计最小、带引擎时间戳的轮端/输入导出可行性，而非回到车身峰值盲调。
3. **原控制路线继续停止自动扩展。** A/B普通制动仍严重超限；固定手动挡可隔离空挡等待，却没有得到舒适停车资格。不增加PID、Ackermann Jerk、半制动扭矩变体或车型搜索。P1保持M6-E NoGo，Sham只解释混杂。
4. **G1独立候选地位不变。** 新位置试验只按实际自然回滑支持判断，阴性不计正例。合成丢帧/目标变更/侧滑测试不等于实际保护灵敏度。正常恢复策略没有新增。
5. **时间合同不改。** 轮端RPC关联外层同步帧，不能假设具备子步时间；Physics重建后即使frame不变也发生隐状态变化。严格20Hz、共享GPU及原Worker故障矩阵保持开放。

后续若获批准，可研究同一0916版本中固定执行器输入和轮胎接触状态的可解释性，先确认平滑输入、扭矩分解与子步采样，再决定单参数族试验是否有依据。不得依据当前有限轮端相关性直接批准Physics修改或停车控制器研发。完整驾驶工程的原三米间距、故障降级和舒适性门槛均保持。

正式数字和证据索引见`reports/m6f_acceptance.json`与`reports/m6f_summary.md`。未执行工作包明确NotRun。
