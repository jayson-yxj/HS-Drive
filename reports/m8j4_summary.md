## 标签结果及其含义

1276 条 Vehicle/Walker Actor-帧记录中，712 条有可见区域证据（55.80%），541 条 Unknown（42.40%），23 条 Invalid（1.80%）。Valid 只表示几何及保守关联条件得到支持，不是经过独立真值认证的标签。

| 类别 | Valid | Unknown | Invalid | 排除倾斜后正样本候选 |
|---|---:|---:|---:|---:|
| car | 641 | 511 | 0 | 640 |
| pedestrian | 71 | 30 | 23 | 71 |

另有 933 条 traffic_light、1532 条 traffic_sign 记录，缺少适用的八角点参考或模型类别，均保留 Unknown，不生成伪造 Box。全部 3741 条非自车记录均保留。711 条正样本候选分布于 212 组数据；进一步限制 PETR 空间范围和实际图像裁剪后为 545 条（474 car、71 pedestrian），仍覆盖 212 组。它们来自**一个片段**，不是 711 个独立目标或场景。

1322 个具有有效图像投影的 Actor-view 中，758 个关联有支持（57.34%），564 个 Unknown（42.66%）。所有 7656 个 Actor-view 中另有 6334 个 Invalid，主要表示该相机外或投影不成立，不等于物理目标不存在。四个相机有支持关联；CAM_FRONT_RIGHT、CAM_BACK_RIGHT 没有通过当前保守规则的正关联，不能据此宣称这些相机没有目标。远场支持和重叠关联仍不足。

发现一个渲染 token 在不同帧关联到多个 Actor。第一次输入门禁因此失败，错误日志保留。随后将该 token 的 39 条关联全部降为 Unknown，并写入新的 reviewed_sidecar；原始侧车、阈值和失败记录未覆盖。歧义来源可能包括几何遮挡、编号复用或截断，尚无法确定。活跃歧义关联为零是隔离结果，不是身份问题已解决。

Instance 使用的 UE 对象编号与 CARLA Actor Registry 编号不是同一命名空间。官方 0.9.15 源码支持 R 为语义、G/B 为 UE GetUniqueID 的低 16 位；本片段没有可验证的捕获二进制身份，因此不能把版本源码当作该次执行的完全证明。依据见 [关联报告](m8j4_instance_association.json)。

23 条地下行人均为同一 Actor 的连续记录，HS Ego 高度为 −100.039 至 −99.910m；138 个视图均无有效投影，对应 Instance 和 Semantic 图中行人语义像素均为零。这支持排除其正监督，不证明具体隐藏机制或真实接触状态；也不产生任何 Free/背景负样本。见 [逐项审核汇总](m8j4_anomaly_audit.json)，完整逐条记录仅在私有目录。

## 前向和标定

保留 Bench2Drive 实际 1600×900 图像及逐摄 K/T，采用原官方测试预处理：缩放 0.88、从 y=280 裁剪为 1408×512，K 同步左乘图像变换。RGB 加载器顺序为 front、front_left、front_right、rear_left、rear_right、rear。进入模型的形状为 [1,6,3,512,1408]。

原 PETR 在 batch=1 时原地 squeeze，执行日志中的 input=[6,3,512,1408] 是调用后的张量形状，不是遗漏 batch 或只输入一台相机。该解释作为追加报告保留，原始 GPU 日志没有改写。特征形状 [1,6,2048,16,44]；六层输出分类及 Box 均为 [6,1,900,10]，每帧解码 300×9，所有值有限。Box 转换与官方八角点的最大残差小于 2.5×10⁻⁶m。

| Ordinal（不是原始 Frame） | 模型前向 ms | 读入/预处理 ms | H2D ms | 解码 ms | 单帧总计 ms |
|---|---:|---:|---:|---:|---:|
| 00000，冷启动 | 1512.945 | 456.907 | 8.678 | 103.904 | 2134.878 |
| 00107 | 518.486 | 364.305 | 8.206 | 1.776 | 904.790 |
| 00213 | 516.953 | 374.923 | 8.721 | 0.730 | 912.886 |

PyTorch 峰值 allocated **1.030 GiB**、reserved **1.252 GiB**；这不是整个 GPU 或进程的显存用量。运行器共 16.194 秒，包含构建/加载等开销。单帧总计包括检查与 CPU 转换，不包括模型构建/加载和结果写盘。没有额外预热、训练或延迟调参；三个样本不足以估计 P95 或认证实时性。

558 个权重张量严格加载，35,805,405 个参数，前后权重完全一致。原始 Checkpoint SHA256 为 16d8a4875c36e7d1cba75b357901ff031b18d9d9374f12780b9b72cc621cefad；已存在的安全数值权重 SHA256 为 cf33dccb1d549c425a89cf346d6f05401c49f6cccbd5a579cb7d8937b5a6d591。详见 [真实 GPU 证据](m8j4_model_forward.json)。

GT 只用于推理前的合同门禁及推理后的独立比较。模型进程只读取数值 RGB/K/T 输入，禁用网络，Python 文件访问钩子拒绝 GT canary；这不是抵御恶意 native code 的文件系统沙箱。

## 可比较性与剩余前置条件

三帧的共同类别/有效裁剪/空间范围内正 GT 候选分别为 0、3、2。模型输出可转换到相同 HS Ego Actor Box Center、完整 l/w/h、CCW Yaw；速度未验证。共有 900 个输出保留在私有目录。0.1 阈值沿用原 M8-B，仅用于描述，未据此选择模型。未匹配预测保持“参考不完整、未知”，不直接判为误检；不报告 AP、Precision、Recall 或泛化。私有最近邻图也不构成一对一检测评价。

下一项可准备的是 **1–4 帧人工确认的小样本学习检查**，实施前仍需：

1. 人工逐对象核验选中可见 car/pedestrian 的身份、Box、遮挡和背景标注完整性；本轮自动支持不是人工签核。
2. 明确检测匹配及损失中的 Unknown/Ignore。标准 PETR 会对未匹配 query 施加背景分类损失，不能直接把当前部分标签交给原训练器。
3. 在训练中保持 GT 与 RGB 输入分离，校验中心/底中心、Yaw、类别、范围、裁剪及无效速度屏蔽；不使用 uint8 Depth 作精深度。
4. 预先限定步数、冻结范围、梯度和坍缩检查。单片段过拟合不能用于证明泛化，独立泛化需要另行授权的独立数据。

原始 Frame/Timestamp、逐传感器同步证据仍缺失；ordinal 只作文件索引。expert_assessment 序号错位继续隔离。未构建 Occupancy Free，未使用 LiDAR/Radar/Top-down/GT 作为模型输入。既有许可证冲突记录保留，本轮不重新分析。**TrainingReadinessNoGo 与视觉安全未验证状态不变。**
