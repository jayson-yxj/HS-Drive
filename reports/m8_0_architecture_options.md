# M8-0 规划计算架构选项

**后续若立项在线规划，倾向方案 B：独立有界核心，M7 完整评价器保留为离线参考。现在不实现 A 或 B；下一主优先级为受控视觉可行性证据补齐。**

依据 `b3dab191485dfe6da883d0d361064f02522b1a9c`。本报告是设计比较，工期、收益和容量均为待验证估计，不是性能成绩。实测口径见[计算预算](m8_0_compute_budget.md)。

## 现有工作量来自哪里

[M7-E replay](../tools/m7e_replay.py) 基于 [M7-D 几何](../diagnostics/m7d_geometry.py)、[M7-C 几何准备](../diagnostics/m7c_geometry.py)、[动态假设](../diagnostics/m7b_motion.py)及[区域缓存](../diagnostics/m7e_region.py)运行。单快照不仅生成轨迹，还查询道路、构建 Actor 假设车身、审核未来道路支持、检查每条候选完整车身与 guide、执行动态 SAT 和停车余量，最后构造详细科学结果并序列化。

主要规模维度是候选数 C、Actor 数 A、每 Actor 假设数 H、时间段数 T、guide 几何点数 G 和道路边界复杂度。现有六秒/0.05s 未来检查含 120 段、121 个时间样本；加速度与延迟组合在去重前有 16 个名义假设。轨迹自身采样与 guide 密集几何采样另计，不能把减少 guide 点等同于无损减少时间预测。

粗略工作量可写作 `C×(轨迹段数+G)×道路/车身检查 + C×A×H×T 动态检查 + A×H×T 未来道路支持 + 慢行余量`。这是定位规模风险的结构表达，不是 WCET 证明；早停、几何复杂度和本地 CARLA Map 查询也改变耗时。当前已有 NumPy 批量 SAT 及 GEOS 原生几何运算，不能把它描述为“全部纯 Python，编译一下就会快”。

F 的 12m、0.02m 连接本身约 601 个点，加后续路径后开发样本 guide 中位数约 716/727.5；旧 keep/stop/E 通常为 161。F 生成约 2ms，完整道路/车身审核 P95 却约 198ms，增量主要应从审核工作研究，不能只优化五次曲线生成。当前聚合计时尚不能把 guide 与精确 Waypoint 成本完全分开。

## A：保留 Python 研究 Planner，优化实现

保留候选、检查顺序及完整评价语义，预计算固定地图区域，批量整理几何数组，减少重复 dataclass 深拷贝，针对实测热点评估一个编译型几何/碰撞内核。接口层仍由 Python 组织。不开启无界缓存，不以放大时间有效期换取通过。

| 方面 | 评估 |
|---|---|
| 复用 | 原请求、候选、拒绝原因和回放工具可直接配对，205/1662 与 7/7 是现成回归起点 |
| 可能收益 | 地图 union/buffer 提前处理；同快照 Actor 几何只建一次；减少对象拷贝；把批次边界而非每点留在 Python |
| 实测限制 | M7-E 静态区域命中约 99% 仍未降低完整 P95；SAT 已向量化，单独编译 SAT 或替换 JSON 无法依据现有数据证明 <200ms |
| 验证难点 | 双精度边界、孔洞、车身旋转、地图高度/车道身份、浮点顺序和早停拒绝语义；等价不仅比较最终 selected |
| 失效处理 | 地图缓存未准备、容量溢出、未知分支、输入缺失及超时必须拒绝/降级；不能临时在控制线程重做完整慢检查 |
| 单人维护 | 前期改动较小，但研究日志与在线工作负载仍耦合；每增加候选/假设都有无界增长风险；多语言内核增加构建矩阵 |
| 规划工量估计 | 约 2–4 人周可完成一次有限离线优化与差分验证；不包含在线资格和车辆执行，失败后停止追加优化 |

A 适合维持研究生产率或做一个独立热点原型，不宜在缺少工作量界限时承诺在线架构。M7-C 的相同输入预热 <200ms 不是 A 在真实移动快照上的资格证据。

## B：独立有界在线核心，M7 作为离线 Oracle 评价器

单独定义受限运行域、候选容量、Actor/假设容量、几何复杂度、固定内存及时效合同。在线输出只包含轨迹、原始时间戳、适用域、完整性状态、必要安全证据和故障原因；逐候选研究解释及 JSON 归档从控制关键路径移出。完整 M7 评价器在相同快照上做离线差分和反例检查。

建议仅选一个编译核心实现路线，例如 C++ 库加 Python 测试适配层，避免同时引入多套框架。这是设计候选，没有选定工具链或实施授权。

| 方面 | 评估 |
|---|---|
| 复用 | M7 的真实起点连接约束、六秒假设、车身/道路/余量合同、反例与时序记录作为规格和测试参考 |
| 可能收益 | 固定容量连续数组、地图空间索引、批量/编译几何及轻量交付有机会同时减少对象、查询、调度开销；收益尚未测量 |
| 验证难点 | 新实现可能与旧实现共享规格错误；必须另有边界见证、独立几何参考和新最终场景，不能只让 B 学会复制旧错误 |
| 失效处理 | 明确 `OutOfDomain / CapacityExceeded / MapUnavailable / PredictionUnsupported / Expired / NoFeasibleCandidate`；不能将未检查对象丢掉或将未完候选当安全 |
| 单人维护 | 建立期成本高，需要维护参考与核心两份实现；后期可冻结参考，仅通过版本化差分测试更新，避免研究功能不断进入热路径 |
| 规划工量估计 | 约 4–8 人周可得到限定运行域的离线原型及差分证据；在线故障、执行与新场景验证另计，不能给出完成日期或保证 |

M7 参考不是物理安全真值；B 与其一致仅是一项必要证据。参考未支持的横穿、分支意图、车辆动力学不能通过重写核心自动变成支持。几何优化不允许缩短六秒预测、删除 3m 原余量条件或缩小车身包络。

## 预处理、快照计算和执行前检查的边界

| 计算/数据 | 允许提前处理 | 每次必须新鲜的内容 | 不能异步延后的判定 |
|---|---|---|---|
| OpenDRIVE 拓扑、合法车道、孔洞、路口静态边界 | 可按地图 SHA/几何版本/车道方向预处理、建立空间索引 | 当前路线意图、道路适用范围、地图身份 | 道路证书缺失/版本不符必须拒绝 |
| Ego Footprint 模板及静态几何核 | 可按车型尺寸、中心偏置、误差裕量预处理 | 当前位姿、有符号速度、状态质量和具体轨迹的全车身包络 | 起点不一致、曲率/加减速约束、真实包络越界 |
| Actor 原型尺寸 | 仅已确认不变的原型 | 最新 Actor ID、盒中心/尺寸/朝向/速度/时间、生成/消失事件 | 未知/缺失对象不能变成 Free；同快照全部相关 Actor 覆盖 |
| 动态假设模板 | 可预定义加速度/延迟族和数组布局 | 以本次快照重建轨迹、走廊支持、碰撞与停车余量 | 动态通过结论不得跨帧缓存，最终执行前状态变化必须处理 |
| Guide Path | 固定地图中心线/拓扑可预计算 | 实测起点连接、路线分支、当前车身可行性 | 未审核的完整 guide 不能用于候选准入 |
| 轨迹时间律 | 可缓存纯数学基函数 | 原始时间、当前速度/可信加速度、障碍及停车目标 | 输出位置/速度一致、停止安全条件及超时拒绝 |
| 诊断与归档 | 可由有界异步队列写入 | 完整性、丢日志计数、源 ID | 必需安全证据和有效期必须在控制前可用；落盘不是安全证书 |

静态索引“快速接受”只能发生在有保守几何包含证明的内区。孔洞、边缘、高度重叠、连接车道和逆向车道必须被证书覆盖。没有证书时回退可靠检查；若可靠检查不能在剩余预算内完成，就拒绝该候选，不能快速放行。静态地图可行驶也不代表动态路面空闲或交通规则允许。

缓存要求：完整 Map SHA、坐标/几何版本、Road/Lane/Section、车型/偏置/裕量、路线身份；精确输入可缓存几何，但时间有效性每次重查。设容量、内存和准备时间上界；预热属于启动门禁。不可缓存动态接受、把坐标量化后复用安全结果、在控制路径全量清空再重建。只改变静态内容才复用，地图切换或车型改变须显式失效。

## 方案决策及退出条件

若单独批准规划研究，优先 B 的**离线有界原型**，不是立即替换生产 Planner。A 可用于一次热点可行性验证，但不与 B 同时全面开发。阶段性证据至少包括：

1. 原 205/1662、7/7 及全部真实序列配对；记录所有拒绝原因、冲突集合、候选选择和差异解释。
2. 独立几何边界/旋转/窄障碍/高速相对运动/多 Actor/道路孔洞与分支测试；未知空间不获准入。
3. 上界输入容量、冷缓存、地图切换、坏输入、Worker 失败及超时下的完整交付；不能只报均值或核心 P95。
4. 5Hz 新计划与 20Hz 控制间的连续有效覆盖证明；[预算报告](m8_0_compute_budget.md)指出 200ms 年龄合同的交接问题尚未解决。
5. 后续另行批准的真实执行与新最终场景，独立评价进度、跟踪、碰撞、停车动力学和退化占比。

离线原型只要出现不能解释的危险接受、无法界定输入规模或无法证明时效交接，就保持 OnlinePlannerNoGo，不用新测试集反复调规则取得偶然通过。

先做视觉 P0 的理由是项目目前没有合格 RGB 3D 基线，而成熟方案尚停在资产阶段；一个有退出条件的小范围前向验证能直接决定未来感知主线。规划 B 的价值明确但工量和未解安全合同较大，在这个信息缺口补齐前全面重建会继续把单人资源集中于 Oracle 子系统。[最终 ADR](../docs/M8_0_ARCHITECTURE_DECISION.md)。
